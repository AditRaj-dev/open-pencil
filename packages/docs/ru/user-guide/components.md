# Компоненты

Component — это переиспользуемый элемент дизайна. После изменения main component все связанные instances обновляются автоматически.

## Assets

Откройте вкладку **Assets** на левой панели, чтобы увидеть локальные components и подключённые библиотеки. Доступны grid view, list view и поиск по имени. При выборе component отображаются подробные сведения о нём.

Добавить asset на холст можно нажатием, клавишей <kbd>Enter</kbd> или перетаскиванием. Локальные assets сгруппированы по исходным страницам. Assets из библиотеки остаются доступными без сети, если соответствующая revision уже была загружена.

## Создание component

Выделите frame или group и нажмите <kbd>⌥</kbd><kbd>⌘</kbd><kbd>K</kbd>. В Windows и Linux используйте <kbd>Ctrl</kbd> + <kbd>Alt</kbd> + <kbd>K</kbd>.

Если выделено несколько объектов, OpenPencil помещает их в новый component с границами по общему bounding box.

Над component отображается фиолетовая подпись со значком ромба.

## Component sets и variants

Выделите не менее двух components и нажмите <kbd>⇧</kbd><kbd>⌘</kbd><kbd>K</kbd> или <kbd>Shift</kbd> + <kbd>Ctrl</kbd> + <kbd>K</kbd>. OpenPencil объединит их в component set с пунктирной фиолетовой рамкой и padding 40 px.

Каждый component внутри set может задавать значения нескольких variant dimensions, например `Size=Small`, `State=Hover` и `Theme=Dark`. Необязательно создавать все возможные сочетания. Верхний левый variant используется по умолчанию и становится fallback, если после обновления точное сочетание отсутствует.

На панели свойств component можно добавлять, переименовывать, менять местами и удалять dimensions и их значения. Одинаковые сочетания значений создать нельзя.

## Component properties

Components и component sets поддерживают переиспользуемые свойства трёх типов:

- text;
- boolean visibility;
- instance swap.

Свяжите property с полем дочернего объекта. После этого значение можно менять в instance без detach. Определения properties и назначенные значения сохраняются в `.fig`.

## Библиотеки компонентов

Библиотека публикует components как неизменяемые revisions. У каждого опубликованного asset есть постоянные library ID, asset ID и revision ID. Поэтому разные instances могут оставаться на разных revisions до явного обновления.

### Публикация

1. Создайте components и component sets, которыми хотите поделиться.
2. Откройте **Assets → Manage libraries**.
3. Выберите **Publish library**.
4. Укажите постоянный library ID и отображаемое имя. После первой публикации ID изменить нельзя.
5. При необходимости найдите нужные изменения в списке и добавьте описание revision.
6. Отметьте добавленные, изменённые, переименованные или удалённые assets, которые нужно включить.
7. Проверьте место публикации и нажмите **Publish library**.

При следующих публикациях неотмеченные изменения останутся в ожидании. Неизменённые assets сохранят прежние определения. Удалённые определения останутся доступными, пока документы ссылаются на их исторические revisions.

### Подключение и вставка assets

Откройте **Assets → Manage libraries** и включите библиотеку. Её components появятся рядом с локальными. Добавьте asset нажатием, с клавиатуры или перетаскиванием.

Опубликованные определения доступны в потребляющем документе только для чтения. Чтобы изменить определение, отредактируйте исходный документ и опубликуйте новую revision. Связанные instances по-прежнему можно настраивать через component properties и overrides.

### Проверка и принятие обновлений

Откройте **Manage libraries → Updates**, чтобы найти новые revisions. Сам поиск ничего в документе не меняет. Можно сравнить текущий и обновлённый instance, перейти между затронутыми instances, а затем обновить:

- выбранный instance;
- все instances одного asset;
- instances на текущей странице;
- instances на всех страницах.

OpenPencil сохраняет совместимые text, visibility и instance-swap assignments. Если точного variant больше нет, до подтверждения обновления будет показан верхний левый fallback. Применённое обновление можно отменить через Undo.

### Локальная работа, storage и offline mode

Библиотека может храниться в локальном каталоге браузера или у настроенного storage provider. При удалённой публикации используются неизменяемые revision objects и условно обновляемый указатель latest, поэтому два автора не могут незаметно перезаписать изменения друг друга.

Загруженные revisions сохраняются локально. Без сети документ продолжает отображать их определения и позволяет вставлять соответствующие assets. Ошибки integrity check показываются пользователю, а не скрываются данными из cache.

### Сохранение потребляющего документа

Подключения к библиотекам и материализованные определения сохраняются внутри `.fig`. После повторного открытия документа связанные instances и revision IDs остаются на месте, даже если удалённая библиотека недоступна.

## Создание instance

Нажмите component правой кнопкой и выберите **Create instance**. Новый instance появится на 40 px правее исходного component и будет выглядеть так же.

Эта команда находится только в контекстном меню; отдельной кнопки в toolbar нет.

## Detach instance

Выделите instance и нажмите <kbd>⌥</kbd><kbd>⌘</kbd><kbd>B</kbd> или <kbd>Ctrl</kbd> + <kbd>Alt</kbd> + <kbd>B</kbd>. Instance превратится в обычный frame и потеряет связь с main component. Все overrides сохранятся как обычные значения.

## Go to main component

Нажмите instance правой кнопкой и выберите **Go to main component**. OpenPencil перейдёт к исходному component, при необходимости переключит страницу и выделит его.

## Синхронизация

После изменения component связанные instances обновляются автоматически. Синхронизируются:

- ширина и высота;
- заливки, обводки и эффекты;
- opacity и corner radii;
- параметры layout, включая Auto layout;
- свойство Clips content.

Синхронизация выполняется после изменения, перемещения или изменения размера дочерних объектов component.

## Overrides

Instance может переопределять отдельные свойства, не разрывая связь с component. При следующей синхронизации переопределённое свойство сохраняется, а остальные продолжают обновляться из main component.

### Доступные overrides

Для дочерних объектов можно переопределить имя, текст, font size, font weight, font family, а также visual и layout properties: заливки, обводки, эффекты, opacity, corner radii и размеры.

### Новые дочерние объекты

Если добавить дочерний объект в component, его копия автоматически появится во всех существующих instances. Порядок дочерних объектов в instances соответствует main component.

## Выбор дочерних объектов

Components и instances ведут себя как единые контейнеры: первое нажатие на дочерний объект выделяет контейнер. Дважды нажмите component или instance, чтобы войти внутрь и выбрать его содержимое.

## Обозначения на холсте

| Элемент | Вид |
|---------|-----|
| Component | Постоянная фиолетовая подпись со значком ромба |
| Instance | Постоянная фиолетовая подпись со значком ромба |
| Component set | Пунктирная фиолетовая рамка |

## Сочетания клавиш

| Действие | macOS | Windows / Linux |
|----------|-------|-----------------|
| Создать component | <kbd>⌥</kbd><kbd>⌘</kbd><kbd>K</kbd> | <kbd>Ctrl</kbd> + <kbd>Alt</kbd> + <kbd>K</kbd> |
| Создать component set | <kbd>⇧</kbd><kbd>⌘</kbd><kbd>K</kbd> | <kbd>Shift</kbd> + <kbd>Ctrl</kbd> + <kbd>K</kbd> |
| Detach instance | <kbd>⌥</kbd><kbd>⌘</kbd><kbd>B</kbd> | <kbd>Ctrl</kbd> + <kbd>Alt</kbd> + <kbd>B</kbd> |

## Советы

- Изменение текста внутри instance создаёт override, поэтому последующее изменение component не перезапишет этот текст.
- Component sets подходят для variants с несколькими dimensions, например размером, состоянием и темой.
- Публикуйте assets из исходного документа: опубликованные определения намеренно доступны потребителям только для чтения.
- Перед принятием revision проверьте обновление, особенно если в новой версии удалено точное сочетание variant values.
- Все команды для components перечислены в разделе [Контекстное меню](./context-menu).
